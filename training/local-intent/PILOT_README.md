# Як працює пілотний корпус соціальної інженерії

Цей експеримент перевіряє, чи навчання на контрастних діалогах допомагає компактній моделі розпізнавати ризиковані прохання під прикриттям авторитету. Приклади синтетичні; вони не є підтвердженими реальними атаками. Авторські мітки перевірені під час підготовки, але **незалежна людська перевірка ще потрібна**.

## Дані та розділення

[social-engineering-pilot.json](social-engineering-pilot.json) містить 90 діалогів, об'єднаних у 30 сімейств. Для кожного сюжету є безпечне, неоднозначне й небезпечне завершення. Теми: керівник, офіційна установа, журналіст/ЗМІ — по 30 діалогів.

У кожній темі перші шість сімейств належать train, два наступні validation, останні два test. Це фіксоване авторське розділення, не статистично репрезентативна вибірка. Усього 54/18/18 діалогів. Близькі контрасти одного сімейства ніколи не розходяться між частинами. Збережено початкові 171 навчальний і 40 відкладених прикладів старого набору.

Кожна вхідна репліка має своє `expected`:

- `kind`: `safe`, `threat` або `ambiguous`;
- `label`: відомий тип, `SAFE` або `null` для неоднозначного випадку;
- `maxAction`: максимально допустимий вплив у дослідницькому сценарії, а не команда розширенню.

`atMs` — відносний час у розмові. Вихідні слова користувача зберігаються для читання діалогу, але не мають мітки загрози й не стають ознаками моделі. Мітка останньої репліки не переноситься на початок розмови.

Приклад сімейства: представлення журналістом → відповідь користувача → прохання.

- Безпечно: анонімно розповісти про громадський транспорт без особистих документів.
- Неоднозначно: залишити контакт для інтерв'ю без уточнення процедури. Це не підтверджена загроза; відмова моделі давати впевнений вердикт є дослідницькою ціллю.
- Ризиковано: надіслати паспорт і домашню адресу в чат для допуску до інтерв'ю.

Представлення керівником, журналістом чи установою **саме по собі не є доказом підробки або загрози**. Клас `MILITARY_SABOTAGE_RECRUITMENT` використано для конкретних прохань приховано передати непублічні військові дані, із секретністю чи винагородою, а не для згадки військової теми. Це використання існуючої категорії теж варто перевірити при незалежному перегляді міток.

## Навчання

```sh
npm run classifier:pilot
```

[Підготовка](../../scripts/local-classifier/pilot-data.ts) додає тільки відомі мітки з train. Неоднозначні завершення пропускаються; їх не перетворюємо на SAFE. Спільні невинні початки сімейства враховуються один раз. У поточному наборі це 54 нові навчальні записи: 18 початків, 18 безпечних завершень, 18 загроз. Разом — 225 навчальних прикладів.

Залишаються 8192 ознаки, 65 544 параметри, попередні алгоритм, seed, 220 епох і пороги. Ніякого нового довгого контексту чи додаткової нейромережі цей експеримент не додає. Модель-кандидат і її набір зберігаються у `.cache/local-classifier/social-pilot-*`; файл моделі розширення не перезаписується.

## Перевірка

[Звіт](PILOT_REPORT.md) порівнює стару й нову моделі на:

- усіх попередніх development/regressions/holdout;
- старих відкладених 40 прикладах;
- нових validation/test;
- нешкідливих початках діалогів;
- неоднозначних завершеннях окремо від точності відомих класів.

Сирий кандидат і прийняте після порогів рішення наведено окремо. `ABSTAIN` означає відмову від впевненого рішення, не безпеку. Потенційні зайві блокування — лише діагностика зіставлення типу з дією, без runtime-арбітражу. Жодних фактичних дій модель-кандидат не застосовує.

Кожен checkpoint використовує останні чотири вхідні репліки віком до 60 секунд, як у поточному shadow runtime. Два сімейства мають паузу 180 секунд: початкова репліка вже відсутня у контексті. Тому цей пілот перевіряє короткі діалоги та обмеження поточного вікна, **не доводить розпізнавання поступового входження в довіру протягом годин чи днів**.

## Як розширювати

Додавайте нові цілі сімейства із трьома контрастами, часовими позначками, поясненням мітки й очікуванням після кожної вхідної репліки. Переглядайте їх вручну, особливо неоднозначні прохання й військову категорію. Не використовуйте вже прочитаний test як основу для підгонки навчальних фраз: наступне вдосконалення потребуватиме нового відкладеного набору.

[Тести](../../tests/unit/heuristics/social-engineering-pilot.test.ts) перевіряють розділення сімейств, хронологію, відсутність майбутнього тексту, відсутність неоднозначних SAFE-міток, незмінність старого набору, збіг вікна з ChatSessionState і незмінність runtime-моделі.
