# Навчений локальний класифікатор: експеримент у режимі спостереження

Це справжня навчена **лінійна модель**, а не LLM і не новий список регулярних виразів. Вона порівнює текст із вагами, отриманими під час навчання, та повертає один із восьми класів: SAFE і сім типів локальних загроз. Генерувати текст чи міркувати як Groq вона не вміє.

## Як відтворити

З кореня репозиторію:

```sh
npm run classifier:prepare
npm run classifier:train
npm run classifier:evaluate
npm run classifier:compare
npm run classifier:pilot
```

Підготовка читає тільки [development](../../tests/evaluation/corpus/development.json) і [regressions](../../tests/evaluation/corpus/regressions.json). З 213 сценаріїв два містять лише слова користувача: їх не використовуємо для навчання вхідних повідомлень. Решта 211 перетворюються на [dataset.json](dataset.json): 171 навчальний і 40 відкладених прикладів. Близькі дублікати об'єднуються у групи; група цілком потрапляє в одну частину. Об'єднання за схожістю тексту не гарантує незалежності всіх сюжетів: корпус невеликий і переважно синтетичний.

Мітка належить **усьому кінцевому вхідному контексту сценарію**, не кожній його проміжній репліці. Текст користувача виключено. Holdout не використовується ні для навчання, ні для вибору порогів. Але він раніше використовувався для розвитку правил: нинішнє порівняння на ньому є історичним, а не незалежним доказом якості.

Навчання перевіряє точну відповідність набору вихідним корпусам, відсутність перетину груп і наявність усіх класів. Фіксовані порядок даних, seed і кількість епох роблять результат відтворюваним. Після редагування корпусу потрібно повторити всі три команди. Не підганяйте модель під holdout; збирайте новий незалежний набір перевірки.

## Що саме навчається

[Спільне виділення ознак](../../src/heuristics/linear-features.ts) використовує слова, сусідні пари слів, символьні 3/4-грами та рамки запитів із чинного RequestAnalyzer. Жодна готова відповідь евристик не є ознакою. Хешування дає 8192 ознаки; L2-нормалізація обмежує їх масштаб. Класові ваги компенсують різну кількість прикладів.

[Навчання](../../scripts/local-classifier/train.ts) — multinomial logistic regression, SGD, 220 епох. 8 × 8192 ваг плюс 8 зміщень: **65 544 параметри**. Ваги збережені як int16, у браузері один раз декодуються у Float32Array (256 KiB). Модель [local-intent-v1.json](../../src/heuristics/models/local-intent-v1.json) не містить навчальних повідомлень.

## Робота в розширенні

[ChatSessionState](../../src/heuristics/chat-session-state.ts) після звичайного аналізу додає `localClassifier` до результату. Модель бачить до чотирьох останніх вхідних реплік, не старших за 60 секунд; власні слова користувача не підсилюють її прогноз. Попередні репліки мають меншу вагу. Загальний ліміт — 4096 символів, до 2048 на репліку, до 32 рамок запиту.

Наприклад, для «Для отримання виплати надішліть мені CVV та код із SMS» вона повертає кандидата `PAYMENT_CREDENTIAL_THEFT`. Увімкнений дебаг показує спостереження у вкладці подій: тип, внутрішній score, різницю з другим кандидатом, час і статус. Сирого тексту у цьому записі немає.

**Прогноз не змінює confidence правил, повідомлення, hard lock, SAFE чи арбітраж із Groq.** Це забезпечено окремим полем результату й тестом примусового розходження з правилами. Вихідні репліки повторно використовують кеш спостереження; нова сесія очищує кеш.

Score — softmax від навчених балів, **не відкалібрована ймовірність шахрайства**. Впевнений прогноз потребує score ≥ 0.60 та відриву ≥ 0.15. Порожній, обрізаний, невпевнений ввід, пошкоджена модель або перевищення бюджету дають `ABSTAIN`. Пороги фіксовані до оцінювання; їх ще треба калібрувати на незалежних даних. `URGENCY_PRESSURE` та окремий `SEED_PHRASE_THEFT` не підтримуються цією моделлю: для них у навчальному наборі немає окремих міток.

## Як читати результати

Окремий [пілот соціальної інженерії](PILOT_README.md) містить 90 контрастних діалогів про керівника, установу та ЗМІ. Він навчає окремого кандидата на train і перевіряє відкладені сімейства, неоднозначні завершення та всі старі приклади. Поточна модель розширення не замінюється. [Звіт пілоту](PILOT_REPORT.md) відділяє поліпшення сирого типу від результатів після порогів.

[REPORT.md](REPORT.md) показує порівняння, [повний JSON](../../tests/results/linear-classifier-latest.json) — кожен сценарій, виправлення, регресії, macro-F1 і показники окремих класів. F1 виявлення відповідає на питання «чи є загроза», точний збіг і macro-F1 — на питання «яка саме». Навчальну точність не можна використовувати як оцінку узагальнення.

Для впевнених прогнозів precision/recall рахуються лише на покритій частині: разом із ними обов'язково дивіться coverage, точність по всіх прикладах і recallIncludingAbstentions. Інакше відмова відповідати може створити хибне враження високої якості.

## Ресурси та наступний допуск

[Порівняння розмірів](SIZE_COMPARISON.md) перевіряє 8192, 16 384 і 32 768 ознак (65 544, 131 080 і 262 152 параметри) на тих самих даних. Окремі процеси навчання й вимірювання дають змогу порівняти пам'ять без одночасного завантаження всіх моделей. Артефакти більших моделей залишаються у `.cache/local-classifier`, команда не замінює модель розширення. Поточний результат: 35/40 на validation і 94/113 на історичному holdout для всіх розмірів; збільшення параметрів саме по собі не підвищило точність типів.

Скрипт вимірює холодний прогноз і 200 звичайних/довгих запитів на CPU, без GPU, а також піковий RSS процесу. Це вимірювання **процесу Node з моделлю, корпусом і правилами**, не всього розширення у Chrome. Наведені в звіті час і пам'ять не підтверджують межу 500 МБ для всього розширення чи 500 мс на іншому процесорі.

До впливу моделі на захист потрібні нові незалежні дані, калібрування та перевірка всього розширення на цільовому i3/i5: кілька вкладок, довга історія, холодний запуск, штатний локальний AI. Посилений режим поки не додано: спочатку треба довести користь цього експерименту. Поточна модель покращує частину історичних прикладів, але помиляється там, де правила вже правильні.

[Тести](../../tests/unit/heuristics/linear-classifier.test.ts) перевіряють розділення наборів, незмінність правил, кеш, напрямок і давність повідомлень, пошкоджену модель, обрізання, таймаут і обмежений ресурсний тест на поточній машині.
