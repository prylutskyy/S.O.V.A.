# Усунення 24 розбіжностей локального корпусу

Дата: 2026-10-10. Перед початком: коміт анонімізатора `b2e6236`. Живі запити до Groq не виконувалися.

## Результат

- **888/888 офлайн-тестів пройшли** тією самою командою, що використовує evaluate у GitHub Actions: `npm test -- --exclude 'tests/integration/**'`, із JSON reporter для збереження результату. Обмеження workers та глобальний timeout не задавалися у фінальному прогоні.
- Сувора перевірка корпусу: **326/326 точних збігів**, 0 розбіжностей дії, 0 хибних блокувань. Assertion нульової кількості розбіжностей не змінювався.
- TypeScript і production build пройшли; розмір збірки приблизно 1,12 MB.
- GitHub Actions ще не виконувався для цих локальних змін: його статус можна підтвердити лише після push.

## Чому стало 0 замість 24

**22 розбіжності виправлено змінами логіки, 2 — виправленням обґрунтовано неправильних міток.** Це не 24 нові розпізнані загрози. Початковий корпус мав 19 пропусків, одну хибну тривогу та чотири помилки типу.

### Запити й зв’язки

- Заперечення тепер прив’язується до дії переходу: «не працює чат, переходьте» більше не вважається забороною переходу. Водночас «не пропоную перейти» залишається безпечним. Розширено дієслова телефонного контакту й узгодження переходу.
- Уточнено мету підтвердження покупки/особи, запити фото двох боків картки, повного імені в документі, російські конструкції OTP, дієприслівники передавання та змішані seed-фрази. Пароль криптогаманця не конкурує зі звичайним паролем акаунта.
- Конкретне завантаження документа класифікується як IDENTITY_PROBING, коли немає окремого запиту платіжного секрету/пароля. Прямий перехід у месенджер для координації не перетворюється на escrow лише через згадку оформлення замовлення; мета отримання виплати враховується окремо.
- Додано композиційні ознаки переадресації фінансової угоди: контекст продажу/доставки + виплата/резервування/збір + конкретна дія + маршрут передавання. Одне слово про кур’єра чи оплату не є достатнім.
- Для нових військових перефразувань потрібні конкретна дія та захищений військовий об’єкт із запитом розташування/координат, або явна руйнівна дія. Додано англійський варіант запиту зйомки блокпоста. Цитати, приклади й заперечення перевіряються окремо.
- Самостійна перевірка банківського застосунку з відмовою передавати коди більше не отримує семантичне платіжне спрацювання.

У коді немає перевірок ID сценаріїв або готових повних рядків корпусу. Нові умови стосуються зв’язків між дією, об’єктом, метою та каналом, але словникове покриття все ще обмежене.

Рядок з початковими мітками враховує, що нова логіка досі не погоджується із двома переглянутими очікуваннями. Корпусний SHA-256 змінився, тому кінцевий приріст не слід показувати як порівняння незмінного набору. Development і regressions зберегли повний збіг; залишкові помилки були в історичному holdout.

**Holdout тепер явно історичний регресійний набір:** його залишкові помилки використано для розвитку правил на прохання користувача. 100% на ньому не доводить якість у нових реальних чатах. Для незалежної оцінки потрібен новий, заздалегідь заморожений корпус.

## Модель і стабільність CI

Зміни RequestAnalyzer вплинули на ознаки навченої shadow-моделі. Її відтворювано перенавчено на тих самих **171 train-прикладі**, без додавання holdout. Розмір, пороги, кількість епох і режим спостереження збережено: **65 544 параметри**, ваги 256 KiB, без керування блокуванням чи Groq. Оновлено [звіт моделі](../../training/local-intent/REPORT.md) та її машинні результати.

Фінальні сирі типи моделі: 35/40 validation, 100/113 історичних holdout. Це не показник прийнятих після ABSTAIN відповідей: покриття наведено у звіті окремо. Не варто порівнювати приріст із попередніми 94/113 без врахування змін ознак і двох міток.

Два навчальні тести впиралися в стандартні 5 секунд під паралельним навантаженням. Для офлайн-навчання встановлено 30 секунд, усі змістовні assertions збережено. Це не послаблює runtime-вимірювання швидкодії чи вимогу нульових корпусних розбіжностей.
